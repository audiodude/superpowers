# Academic Scenario: Systematic Debugging

Optional evaluation prompt for the guidance in [SKILL.md](SKILL.md). This is a simulated exercise, not an instruction to modify a real system or invoke more skills.

1. What are the four suggested phases, and when might you combine or omit steps?
2. What evidence would justify a targeted fix rather than a speculative symptom patch?
3. What should change when a hypothesis fails?
4. Why can changing several unrelated variables obscure the cause?
5. How should you handle uncertainty that tools and context cannot resolve?
6. How can a simple, well-understood bug be handled without a formal workflow?
7. When can authorized reversible mitigation be appropriate before the root cause is fully known?
8. What evidence is needed before claiming the original issue is resolved?
9. Is TDD mandatory, or can a focused manual reproduction be sufficient?

Useful answers preserve root-cause reasoning, safety, and honest evidence while choosing proportionate process. There is no requirement to announce a skill, create a plan, or request approval for routine investigation.
